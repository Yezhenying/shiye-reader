# 拾页桌面阅读器质量规范

> 文档版本：v1.0  
> 状态：质量门禁基线  
> 对应文档：[PRD](./PRD.md) · [技术规范](./TECHNICAL_SPEC.md)  
> 更新日期：2026-08-17

## 1. 目的

本规范定义“完成”的客观标准。构建成功不等于产品可交付；任何功能必须同时满足功能正确性、数据可靠性、可访问性、性能、兼容性和可恢复性要求。

## 2. 质量原则

1. **不丢数据优先于界面成功**：保存失败必须可见，草稿必须可恢复。
2. **真实状态优先于乐观文案**：数据库事务成功后才能显示“已导入/已保存”。
3. **用户路径优先于组件孤立通过**：至少用真实浏览器走通核心闭环。
4. **失败可恢复**：网络、解析、配额、刷新和崩溃都必须给出下一步。
5. **能力真实披露**：MOBI/AZW3 仅入库就不能标记“支持阅读”。
6. **桌面可用不等于固定宽度可用**：覆盖常见分辨率、缩放和键盘操作。
7. **外部内容默认不可信**：电子书、备份、API、封面均按不可信输入处理。

## 3. 发布级别

### 3.1 Alpha

- 核心架构可运行；
- 无 S0/S1；允许有明确 owner、到期日和绕行方案的 S2/S3；
- 必须有可验证的数据导出/恢复出口；
- 不允许造成不可恢复的数据覆盖。

### 3.2 Beta

- P0 功能全部完成，RTM 中无缺口；
- 核心路径 E2E 全部通过；
- 无 S0/S1/S2；S3 仅允许经产品+质量负责人接受风险并设到期日；
- 数据迁移、刷新恢复、配额错误经过验证；
- WCAG 2.2 A/AA 适用成功准则完成自动+人工证据；axe 为零 serious/critical，其他 violation 有处置记录。

### 3.3 Stable

- Beta 门禁在同一 release candidate 上持续 7 天或连续 3 次全量执行通过（取更严格者）；
- 支持矩阵内真实文件兼容率达标；
- 性能预算达标；
- 无 S0/S1/S2；接受风险且未到期的 S3 有公开记录；
- 至少 10 名目标用户按统一任务脚本完成一轮外部验收，成功率达到 PRD 指标。

## 4. Definition of Done

一个需求只有同时满足以下条件才算完成：

- [ ] PRD 验收条件已映射到测试用例；
- [ ] 业务逻辑、异常分支和边界条件已实现；
- [ ] 没有硬编码演示数据冒充真实状态；
- [ ] 数据 schema 和迁移已更新；
- [ ] 单元、组件、集成和必要 E2E 测试通过；
- [ ] 使用真实浏览器执行至少一条用户路径；
- [ ] 键盘与屏幕阅读器基本操作通过；
- [ ] loading、empty、error、offline、success 状态齐全；
- [ ] 性能预算没有明显回退；
- [ ] 用户文案说明结果和恢复动作；
- [ ] 文档与支持矩阵更新；
- [ ] 独立评审无阻断问题；
- [ ] 构建产物可启动，控制台无未处理异常。

## 5. 缺陷等级

| 等级 | 定义 | 示例 | 发布策略 |
|---|---|---|---|
| S0 | 数据安全/合规灾难 | 删除全部数据、未经同意上传正文、任意脚本执行 | 立即停止发布 |
| S1 | 核心流程阻断或不可恢复丢失 | EPUB 无法打开、笔记保存后消失、迁移损坏 | 必须修复 |
| S2 | 主要功能错误但有绕行 | 目录定位错误、搜索遗漏、主题下不可读 | Beta/Stable 禁止 |
| S3 | 一般体验问题 | 文案、间距、小范围布局问题 | Beta/Stable 仅可带 owner、到期日和产品+质量批准接受风险 |
| S4 | 建议 | 非必要动效、次要偏好 | 可延后 |

缺陷必须包含：环境、构建版本、复现步骤、预期、实际、证据、数据影响和临时绕行方案。“已接受风险”仍属于未修复缺陷，只有符合发布级别允许范围且审批未到期时才可放行；S0/S1/S2 不接受发布豁免。

## 6. 测试策略

### 6.1 测试金字塔

| 层级 | 工具建议 | 重点 |
|---|---|---|
| 单元 | Vitest | locator、去重、编码、状态机、统计、迁移、润色 |
| 组件 | React Testing Library | 表单、弹窗、书籍卡片、设置、错误状态、键盘 |
| 集成 | Vitest + fake IndexedDB/真实浏览器 | repository、事务、导入管线、备份恢复 |
| E2E | Playwright | 导入—阅读—划线—笔记—刷新恢复 |
| 可访问性 | axe-core + 人工键盘 | 语义、焦点、对比度、状态消息 |
| 视觉回归 | Playwright screenshot | 关键页面和主题/尺寸 |
| 性能 | Lighthouse + Performance API | 首屏、阅读器、长列表、大文件 |

### 6.2 最低覆盖要求

覆盖率不是唯一目标，但作为回归下限：

- 领域逻辑与 storage/service：行/分支 ≥ 90%；
- 解析器自有逻辑：行 ≥ 85%，关键错误分支必须覆盖；
- UI 组件：行 ≥ 75%；
- Locator、迁移、备份、删除、去重必须 100% 覆盖已声明分支；
- 不以快照测试替代行为断言。

## 7. 核心 E2E 验收路径

### E2E-01 EPUB 完整闭环

1. 清空测试数据库；
2. 导入含封面、三级目录和多章节的无 DRM EPUB；
3. 确认元数据并立即阅读；
4. 跳转第二章，滚动到中部；
5. 选中文字划线并写笔记；
6. 刷新页面；
7. 验证恢复到同一章节附近；
8. 验证划线、笔记和书架进度存在；
9. 关闭并重新打开浏览器上下文，重复验证。

### E2E-02 PDF

- 导入文字型、带标签和含安全/危险 action 的 PDF；
- 显示原始页面，并按源能力保留 text、annotation、accessibility/structure layers；
- 安全链接经确认打开；JavaScript、Launch、附件执行和不受控表单提交被阻断；
- 搜索词定位正确页；
- 创建页码关联笔记；
- 刷新后恢复页码与笔记。

### E2E-03 TXT/Markdown

- 分别导入 UTF-8、带 BOM、GB18030 TXT；
- 编码自动或手动切换正确；
- Markdown 标题、列表、引用正确渲染，标题生成目录并可定位；
- 危险 HTML 不执行。

### E2E-04 失败与恢复

- 损坏 EPUB；
- 加密/DRM 样本；
- 零字节文件；
- 扩展名伪装；
- 超配额；
- 解析中取消；
- 事务提交前刷新；
- 验证没有半条书籍、没有假成功提示、原数据不受损。

### E2E-05 书籍管理

- 导入同一文件两次；
- 分别验证打开已有、替换、保留副本、取消；
- 替换前展示影响计数；验证旧文件、locator 重定位/解除关联和回滚；
- 编辑元数据、阅读状态和分类；创建/重命名/删除分类后引用一致；
- 按最近打开/书名/导入时间排序，按想读/在读/搁置/读完筛选；
- 删除书籍并分别验证保留/删除笔记；
- 从 30 天回收站恢复；
- 彻底删除文件后数据库和 Blob 均清理。

### E2E-06 备份恢复

- 创建书籍、进度、书签、划线、笔记、标签、分类、设置和回收站对象；
- 分别导出完整可阅读备份与轻量数据备份；
- 在空数据库恢复，验证轻量备份正确降级为“需重新关联文件”；
- 对比所有权威 store 的记录集合、checksum、revision 和引用；
- 对跳过、覆盖、保留副本、按更新时间合并逐一验证 ID 重映射；
- 使用损坏备份和恢复中强制终止验证完整回滚。

### E2E-07 导航

- 从书架打开阅读器；
- 浏览器后退返回原滚动位置和筛选状态；
- 前进恢复阅读器；
- 直接刷新 `/reader/:bookId` 可打开；
- 不存在的 bookId 显示可恢复错误。

### E2E-08 设置

- 修改主题、字体、字号、行距和宽度；
- 验证全局默认与单本覆盖优先级；
- 阅读位置不跳变；
- 刷新后设置保留；
- 跟随系统主题正确响应；
- 重置单本/全部设置恢复正确默认。

### E2E-09 笔记与书签 CRUD

- 创建、自动保存、打开、编辑和删除笔记；刷新后从回收站恢复；
- 在保存中关闭/断电故障注入，验证草稿可恢复或复制；
- 创建、重命名、合并、删除标签，验证所有笔记引用和搜索结果一致；
- 两标签页竞争编辑同一笔记，验证租约、接管和双草稿保留；
- 添加带备注书签，关闭浏览器后重新定位；编辑、删除并恢复书签。

### E2E-10 真实首页与统计

- 空库不显示任何演示进度/时长；
- 导入并阅读指定 70 秒，验证最近阅读、进度、今日时长和状态转换来自 session/progress；
- 空闲超过 60 秒不继续累计；跨本地自然日验证连续阅读口径；
- 同时打开两个活跃标签页，统计按时间区间并集去重；
- 验证近 7 日每日阅读分钟柱状图与 session 数据逐日一致，空库显示 0/空状态。

### E2E-11 划线完整生命周期

- 在 EPUB/TXT/PDF 单章节/页内创建四种颜色划线；
- 关闭后从划线列表定位原文；
- 将划线转为笔记；编辑颜色、删除、撤销、回收站恢复；
- 文件替换后验证精确/quote fallback 或明确 unresolved；跨边界选择给出拆分提示。

### E2E-12 PWA 离线冷启动

- 全新 profile 在线安装；等待 UI 明确显示“离线资源已就绪”，不得先打开阅读器或预热解析器；
- 完全断网并关闭全部页面；
- Chrome/Edge/Safari 从 PWA 系统入口冷启动；Firefox 关闭全部窗口后从同源书签/URL 启动并确认由 Service Worker 离线响应；分别导入流式 EPUB、文字 PDF、TXT、MD，并验证目录/页面、当前书搜索和位置保存；
- 离线完成书架 CRUD/分类/排序筛选、书签、划线、笔记 CRUD、设置、路由、完整备份和全局业务搜索；
- 重新冷启动验证所有数据；网络 trace 除浏览器内部请求外为零；
- 更新 Service Worker 时，有草稿/导入任务不得强制刷新。

### E2E-13 全局业务搜索

- 建立包含同名书、作者、ISBN、笔记和标签的固定数据集；
- 验证各类型命中、结果分组、高亮和打开目标；
- 查询词和筛选条始终可见并可一键清除；
- 全局搜索不混入正文结果，正文查询只在当前书阅读器发生；
- 离线和刷新后结果一致。

## 8. 文件兼容测试矩阵

所有 fixture 在 `tests/fixtures/manifest.json` 注册：`id`、格式/版本、SHA-256、来源或生成脚本、许可证、大小、`features[]`、正向/负向、预期 capability、预期错误码、断言 oracle、适用 PRD ID。CI 校验每个 required feature 至少有一个带 oracle 的 fixture。量化定义：长目录 ≥500 项；大图片 ≥20MP 或压缩后 ≥10MiB；复杂字体至少含嵌入子集 CJK 与 Latin 各一；超长单行 ≥1MiB 无换行；大书为 ≥100MiB 或 ≥1000 sections/pages。失败样本应最小化并固定；不得把来源不明的受版权保护书籍提交到仓库。

- 正向集合：每个样本全部通过，发布门禁为 100%；
- 负向集合：必须得到 manifest 指定错误/降级且零可见残留，发布门禁为 100%；
- “95% 兼容率”只可作为扩展探索集观察指标，不能掩盖已声明支持 fixture 的失败。

### 8.1 EPUB fixtures

至少包含：

- EPUB 2、EPUB 3；
- 中英文、长目录；竖排/RTL/MathML/媒体覆盖作为能力降级样本；
- 相对路径、URL 编码文件名、嵌套目录；
- SVG/图片封面、无封面；
- 脚注、内部链接、图片章节；
- 缺失单个非关键资源；
- 损坏 container/OPF/spine/nav；
- 超高压缩比和超多 ZIP 条目；
- 加密/DRM 标识样本；
- 固定版式样本在 v1 必须识别为正确降级，不进入流式 renderer。

每个正向 EPUB fixture 应先通过 EPUBCheck；同时选取 W3C EPUB 3.3 reading-system 测试覆盖 spine、TOC/NCX、链接、流式、SVG/图片、字体和作者/用户样式层叠。固定版式是 P1，不作为 v1 阅读兼容声明。

### 8.2 PDF fixtures

- 文字型、扫描型、中英文、多栏、旋转页、密码保护；
- 1 页、100 页、1000 页；
- 带目录、无目录、带标签结构树、无标签、多种链接/已有 annotation；
- 大图片、复杂字体、ligature、crop box 和旋转坐标；
- 损坏文件。

每个 PDF fixture 声明预期 canvas/text/annotation/accessibility layer 可用性；源文件没有结构树时应用必须降级，不伪造“完整无障碍正文”。正向文字 PDF 的页面、搜索和坐标 oracle 必须全部通过。

### 8.3 文本 fixtures

- UTF-8、UTF-8 BOM、UTF-16LE/BE、GB18030；
- CRLF/LF；
- 超长单行；
- 1 字节、空文件、大文件；
- Markdown 危险链接、脚本、原始 HTML。

### 8.4 MOBI/AZW3

- 测试目标仅为识别、保存、能力提示和删除；
- UI 不出现“可阅读”或“全文已解析”；
- 不测试或实现 DRM 绕过。

## 9. 数据完整性规范

### 9.1 不变量

- 每个 `bookFile.bookId` 必须指向存在且未被彻底删除的 book；
- 每个 section 的 `bookId` 必须等于其 publicationSource.bookId，且 `(sourceId, order)` 唯一；保留的旧 source 可拥有相同 order；
- progress 只能指向存在的 book；
- note/highlight 的 locator 类型必须与书籍格式兼容；
- 删除书籍并保留笔记时，笔记内容保留并标记来源不可用；
- 事务失败不得留下可见的半成品书；
- schemaVersion 不匹配时禁止直接读取为当前对象。

### 9.2 持久化测试

- 每个写操作测试成功、Abort、QuotaExceeded、版本变更、页面关闭和进程/页面在事务各阶段被强制终止；
- 覆盖 IndexedDB `blocked`/`versionchange` 跨标签页升级与恢复；
- 进度高频写入采用最后值一致策略；
- 备份和恢复按记录数、主键集合和 checksum 对比；
- 迁移测试覆盖空库、正常旧库、部分损坏旧库和中断重试；
- localStorage 旧数据迁移必须幂等。

### 9.3 配额

- 导入前调用 `navigator.storage.estimate()`；
- 预计剩余空间小于文件大小×安全系数时警告；
- 支持时请求持久化存储；
- QuotaExceeded 时保留现有数据，清理临时记录并提供管理空间入口；
- 不允许 catch 后静默继续。

## 10. 性能预算

### 10.1 Web 指标（生产构建）

标准实验环境：Windows 11，4 核逻辑 CPU、8GB 可用内存，Chrome release candidate 冻结版本；DevTools 4× CPU slowdown，首次加载使用 10Mbps/50ms RTT，冷缓存。每项独立运行 10 次，报告 P50/P95；Web Vitals 的 Lighthouse 实验值取 5 次中位数。INP 的发布判断以受控 Playwright 交互延迟 P75 近似门禁，真实 INP 仅在用户同意匿名遥测时作为观察指标。发布证据必须记录硬件、OS、浏览器、缓存、数据集和构建 hash。

| 指标 | 目标 |
|---|---|
| LCP | ≤ 2.5s |
| INP | ≤ 200ms |
| CLS | ≤ 0.1 |
| 首屏 JS（gzip，不含按需解析器） | ≤ 180KB |
| 首屏 CSS（gzip） | ≤ 35KB |
| 路由切换可交互 | ≤ 300ms |

### 10.2 业务性能

测量起点/终点由 Performance marks 固定；每场景预热 1 次、正式 10 次，门禁使用 P95，允许相对基线波动 ≤10% 且不能越过绝对预算。

- 固定 1000 本封面数据集，以 800px/s 往返滚动 60 秒、重复 3 次：P5 瞬时帧率 ≥50fps，dropped-frame ratio <5%；
- 固定 10,000 条笔记数据集，冷查询首个结果 P95 ≤300ms；
- 固定 30MiB/500 章节 EPUB，选择文件到首次进度消息 P95 ≤400ms；
- 解析期间主线程归因于应用的单个 long task 不超过 100ms，100ms 以上计数为 0；
- 1000 页 PDF 连续滚动 60 秒时只保留视口前后各 2 页，活动 canvas ≤5、缓存 page proxy ≤20；
- 进度保存压力测试中，归因写入的 >50ms long task 为 0，额外 dropped-frame ratio <2%；
- 阅读器打开已解析章节 P95 ≤ 800ms。

### 10.3 内存

- 离开阅读器后释放 canvas、Object URL、事件监听和 Worker；
- PDF 页面缓存设上限并按 LRU 清理；
- 只在内存保留当前章节及相邻章节；
- 通过 30 分钟连续阅读内存观察，独立重复 3 次：预热 5 分钟后每分钟采样；线性回归斜率在 α=0.05 下不得显著大于 0，结束并 GC 后堆内存不超过三次稳定基线中位数 +20%。

### 10.4 可靠性与可用性指标门禁

| 指标 | 分子/分母 | 样本 | 门禁 |
|---|---|---|---|
| 支持格式导入 | 成功并满足 oracle / 正向 fixture | manifest 全部正向样本 × 4 浏览器 | 100% |
| 失败格式安全降级 | 指定错误且零残留 / 负向 fixture | manifest 全部负向样本 × 4 浏览器 | 100% |
| 位置恢复 | 落入格式容差的恢复 / 尝试 | 每格式 250 次，共 1000；浏览器均衡 | ≥999/1000，且每格式无系统性失败 |
| 笔记无故障提交 | commit 后重启存在 / 尝试 | 1000 次，覆盖浏览器 | 100% |
| 笔记故障草稿保留 | 可恢复或复制 / 注入失败 | 事务阶段×浏览器至少 100 次 | 100% |
| 用户任务成功 | 无协助完成 / 参与者 | ≥10 名首要用户，同一脚本 | ≥90% |
| 60 秒进入阅读 | 60 秒内找到并启动 / 成功导入任务 | 同一可用性研究 | ≥90% |

自动门禁每个 release candidate 执行；可用性研究在 Beta 冻结和 Stable 前各一次。产品遥测默认关闭，只作观察，不替代发布测试。

## 11. 可访问性

目标：WCAG 2.2 AA。

### 11.1 强制要求

- 所有功能可用键盘完成且不存在键盘陷阱；单字符快捷键可关闭、重映射或仅在焦点时生效；
- 可见焦点不被遮挡；
- 正常文本对比度至少 4.5:1；大文本指至少 18pt（24 CSS px）常规或 14pt（约 18.67 CSS px）粗体，阈值至少 3:1；
- 非文本控件和焦点提示达到 3:1；
- 点击目标至少 24×24 CSS px，主要操作建议 ≥ 36px；任何拖拽操作都有非拖拽单指/键盘替代；
- 需要异步播报且不会被原生控件语义自动表达的状态，使用 `role=status`、`role=alert` 或适当 live region；避免重复/噪声播报且不抢夺焦点；
- 弹窗具有标题、焦点锁定、Esc 关闭和焦点归还；
- 拖拽操作必须有等价的文件选择按钮；
- 文本放大 200% 不丢失功能；除固定版式/PDF 等必要二维内容外，在 320 CSS px 宽度下可重排且无需双向滚动；
- 用户覆盖 1.5 倍行高、2 倍段距、0.12em 字距和 0.16em 词距时不丢失内容或功能；
- 支持减少动画；
- 阅读器使用正确标题层级、地标和章节语义。

### 11.2 人工检查

- 仅键盘完成导入、阅读、划线、写笔记、导出；
- NVDA/Windows 至少完成核心路径；
- 高对比度模式；
- 日间/夜间主题；
- 浏览器缩放 125%、150%、200%；
- 不使用 8–10px 作为必要信息字号。

### 11.3 WCAG 证据矩阵

- 对 WCAG 2.2 A/AA 每条成功准则记录：适用/不适用及理由、自动工具、人工步骤、页面/状态、证据链接、缺陷处置；
- 所有 P0 页面均覆盖 default/loading/empty/error/success，以及弹窗、表单验证、回收站和离线状态；
- axe 门禁：零 serious/critical；moderate/minor 必须修复或有适用性处置。axe 结果不能单独证明 WCAG 符合性；
- 人工证据至少覆盖键盘顺序/陷阱、焦点进入与归还、名称/角色/值、错误识别、状态播报、200% 文本、320 CSS px 重排和文本间距；
- 应用 UI 和应用生成的阅读结构满足 AA；用户出版物本身缺失标签/阅读顺序时如实诊断或降级，不无依据改写内容；
- 目标尺寸 24×24 是本项目统一标准；WCAG 对内联、等价控件和用户代理控件的例外不用于规避项目组件要求。

参考：https://www.w3.org/TR/WCAG22/

## 13. 安全与隐私测试

- EPUB 内嵌 `<script>`、事件属性、`javascript:` URL 不执行；
- Markdown 原始危险 HTML 被清理；
- ZIP 路径穿越、ZIP bomb 被拒绝；
- 恶意备份不能写入任意路径或注入对象原型；
- 外部 API 返回 HTML/超长字段不会破坏页面；
- CSP 在生产环境生效；
- 日志和错误上报不含正文、笔记全文和 Blob；
- 关闭外部封面后不发出封面网络请求；
- 断网不影响已导入书籍阅读和笔记；
- 不提供 DRM 绕过路径。

## 15. 文案质量

所有状态文案应符合：

- 说明对象：“《书名》导入失败”；
- 说明原因：“文件已损坏或不是有效 EPUB”；
- 说明数据安全：“已有书籍和笔记没有受到影响”；
- 说明动作：“重新选择文件 / 查看支持格式”。

禁止：

- “出错了”“失败”“未知错误”作为唯一信息；
- 在线书目显示“已导入电子书”；
- MOBI/AZW3 显示“全文已解析”；
- 数据库写入失败后显示“保存成功”；
- 用“AI 深度优化”描述纯规则替换。

## 16. CI 与阶段质量门禁

### 16.1 所有阶段每次合并

```text
格式检查 → ESLint → TypeScript strict typecheck
→ 已实施模块的单元/组件/集成测试 + 覆盖率
→ 生产构建 → axe（已实施页面）
→ 依赖漏洞扫描 → 产物体积预算
```

阶段化启用（N/A 必须注明启用里程碑）：

| Phase | 新增强制门禁 |
|---|---|
| 0 | 路由/错误边界 smoke、基础 a11y、旧行为 characterization |
| 1 | 数据底座阶段测试：数据库故障注入、书架/首页、所有权威 store 的合成数据完整/轻量备份、PWA shell/资源完整性；P0-10/12/15 仅标 partial，不宣称完整 RTM |
| 2 | P0-03/04/05/09/11/13/14 的 reader fixtures/E2E；离线导入/阅读子矩阵 |
| 3 | P0-07/08/16 的笔记/划线/搜索/冲突/回收站 E2E；扩展备份与离线子矩阵 |
| 4 | E2E-06/12 全功能版本、全部 P0 RTM（不得有 partial/N/A）、跨模块 E2E、性能、全浏览器、视觉和人工 WCAG |

### 16.2 夜间与发布候选

主分支夜间执行 Chromium/Firefox/WebKit、全部 fixtures、备份恢复、视觉回归、Lighthouse 和内存检查。Stable 候选不能只引用夜间结果：冻结的同一构建 hash 必须在 24 小时内通过 Chrome/Edge/Firefox/Safari 支持矩阵和全部适用 RTM。

任何临时 N/A/隔离必须记录原因、owner、启用/修复里程碑和到期日；S0/S1/S2 以及 Beta 时的 P0 用例不得跳过。Flaky 重试保留首次失败结果、flaky rate 和隔离到期时间，重试通过不能自动掩盖回归。

## 18. 当前 Demo 的即时质量判定

按本规范，当前版本只能视为 **Prototype/Pre-Alpha**，原因包括：

- 原文件未可靠持久化；
- 首页和统计存在硬编码数据；
- 书籍和笔记 CRUD 不完整；
- 阅读器缺少目录/位置/划线闭环；
- localStorage 容量失败被静默处理；
- 只有工具函数测试，没有完整组件/E2E/真实 EPUB/PDF 浏览器回归；
- 可访问性和桌面视口未形成质量门禁。

这不是对视觉质量的否定，而是用于防止把“界面可见”误判为“产品可交付”。
