# 拾页：公网部署、界面美化与本地辅助工具优化方案（草稿）

> 状态：本地实现与验证完成；GitHub Pages 工作流已就绪。实际公网发布需用户登录 GitHub 网页创建/上传公开仓库，助手无法代办账户操作。

## Context

当前“拾页”是 React/Vite 本地优先阅读与笔记应用。目标是：

1. 通过 GitHub 发布，让其他人能通过公网 HTTPS 链接访问；
2. 提供“每个人查看自己的内容”的个人空间体验；
3. 在“极简纸张阅读器”视觉方向下提升界面品质；
4. 优先修复书架分类的卡顿与归类不顺畅；
5. 新增纯前端、本地运行的轻度表达优化工具，**不请求、不接入任何外部 API**。

## 已确认的现状

- `package.json` 已提供 Vite 生产构建，当前无 `vercel.json`、`netlify.toml`、Dockerfile 或其他部署配置。
- `vite.config.js` 已生成离线资源清单；项目已有 `public/manifest.webmanifest` 和 Service Worker 基础，因此适合部署为静态站点。
- 所有书籍、笔记、分类、阅读进度等权威数据保存在浏览器 IndexedDB；因此公网部署后，**每个访问者的数据仍独立保存在自己的浏览器/设备内，不会自动共享或跨设备同步**。
- GitHub Pages 可承载静态前端，但不能独立提供真实的账号注册、登录鉴权、权限隔离或跨设备数据同步；本期已选择“每个浏览器独立的本地空间”，不把它伪装为真实账号。
- 已有 `src/textPolish.js` 的 `polishText`：它是本地、确定性的规则润色，不调用模型或网络，适合作为“轻度表达优化”基础，但当前笔记编辑流程未接入预览、采用/保留原文和版本记录。
- 书架现有交互：状态/分类/排序为原生下拉框；新建分类使用浏览器 `prompt`；归类只能从单本书编辑弹窗中选择一个分类；删除分类后才解除书籍引用。逻辑分散且缺少批量归类、分类重命名、清晰的空状态/结果反馈。
- 可复用的数据能力：`src/useLibrary.js` 已有分类新增/删除和 IndexedDB 刷新机制；`src/db.js` 已有分类删除并批量解除书籍引用的事务；`src/domain.js` 已有统计、会话、搜索等本地计算基础。

## 已确认的产品决策

| 维度 | 已确认结论 |
|---|---|
| 发布平台 | GitHub Pages |
| 对外可见性 | 完全公开访问 |
| 个人空间 | 每个浏览器独立的本地空间；不做账号、登录、后端或跨设备同步 |
| 分类模型 | 每本书至多一个主分类，可为未分类 |
| 视觉方向 | 极简纸张阅读器 |
| 表达优化 | 默认关闭、用户主动触发、纯本地规则处理、原文可恢复、摘录永不润色 |
| 仓库建议名称 | `shiye-reader` |

## 推荐产品方向

### 1. 公网部署：GitHub Pages 静态发布 + 明确的数据边界

首期部署采用 GitHub Pages：建议建立公开仓库 `shiye-reader`，使用 GitHub Actions 构建 `dist/` 并发布。默认项目页链接为：`https://<GitHub 用户名>.github.io/shiye-reader/`。

发布实现必须完成项目路径适配：Vite `base` 使用仓库名；`manifest.webmanifest` 的 `start_url` / `scope`，Service Worker 注册 URL、缓存清单请求、缓存回退页和图标地址均从部署 base URL 派生，不能继续写死根路径 `/`。继续保留 Hash 路由，避免 GitHub Pages 缺少服务端重写规则导致深链接 404。

用户在首次访问时应看到简洁的“本地数据说明”：书籍、笔记和设置仅保存在当前浏览器；每位访问者默认只能看到自己当前浏览器内的数据；更换设备/清除站点数据前需完整备份。该说明不打断首次导入。

> **账号边界**：本期采用“本机本地空间”。它让每位用户自然只看到自己浏览器的数据，但不提供注册、登录、找回密码、跨设备同步或真正的访问控制。网站公开，应用源代码也公开；用户导入的书籍和笔记不会上传到 GitHub Pages。未来若要真实账号，需单独立项并引入后端能力。

为降低你对 Git 操作的负担，实施完成后会提供一份“**仅 GitHub 网页端操作**”的发布清单：创建/确认公开仓库、在网页上传源码压缩包（不含 `node_modules`）、在 Settings → Pages 选择 GitHub Actions、等待工作流完成并打开链接。助手无法替你登录或在你的 GitHub 账户中创建仓库，但不要求你使用命令行 Git。

上线验收重点：公网 HTTPS、项目页路径、刷新/Hash 深链接、PWA 安装、离线资源提示、不同浏览器导入、隐私说明和备份入口可用。

### 2. 视觉美化：极简纸张阅读器

保持暖白、低饱和墨色、鼠尾草绿点缀、纸张质感和衬线阅读字体；避免插画堆叠、拟物化书房陈设或装饰性渐变。重点调整：

- **信息层级**：统一页面标题、辅助说明、主操作与次操作的视觉权重；减少同级按钮竞争。
- **书架**：采用更大、更整齐的封面网格；卡片默认只呈现封面、书名、作者、进度；将管理动作放入悬浮菜单或详情抽屉，避免卡片拥挤。
- **工具栏**：将“状态、分类、排序、管理分类”统一为可收起的书架控制区；在筛选后显示结果数和一键清除。
- **阅读器**：强化正文宽度、章节导航和阅读设置的层次，避免工具面板常驻抢夺注意力。
- **动效与性能**：仅使用 150–200ms 的反馈动效；分类/筛选只更新受影响区域，支持“减少动画”。
- **无障碍**：键盘可完成筛选、归类、管理分类；状态变化有可读提示，焦点不丢失。

### 3. 书架分类：建立连续、可批量完成的“归类工作流”

推荐采用“分类侧栏/管理面板 + 多选批量归类 + 详情抽屉”的组合：

1. 书架工具栏中分类以可见筛选 Chips 呈现，而非仅原生下拉框；选中后立即显示结果数量和“清除”动作。
2. 书籍卡片支持进入多选模式；批量操作栏提供“加入分类”“移出分类”“修改阅读状态”。
3. “管理分类”打开应用内面板（不使用浏览器 `prompt`），支持新建、重命名、删除、书籍数量、排序；删除前明确说明受影响书籍会变为“未分类”，且不删除书籍。
4. 单本书详情抽屉可直接更改**唯一主分类**；批量“加入分类”实际语义为“设为主分类”，会替换原分类，并在确认文案中明确提示。
5. 分类写入采用本地事务、乐观更新和失败回滚；筛选结果使用 memoized selector，避免每次输入/切换都重新渲染整面书架。
6. **性能修复重点**：当前任意分类变更都会经 `useLibrary.reload()` 重读全部 IndexedDB store（包含原始文件 Blob 和正文 sections），再重新排序/渲染整面书架。改造后书架只订阅书籍、分类、进度的轻量摘要；原文件和正文只在打开阅读器时按 `bookId` 读取。批量归类只执行一次本地事务、一次局部状态更新和一次跨标签通知；卡片按稳定 `id` memo 化，并采用窗口化或分页渲染，避免切换分类时创建所有封面 URL 和卡片。

### 4. 纯前端辅助工具：轻度表达优化

目标不是 AI 代写，也不改写原意，而是让用户写下的大白话想法更清晰、克制、可回看。所有处理只在浏览器内执行；不发送正文、书名、笔记或行为数据到任何服务。

首期采用“**轻度润色**”单一模式，基于现有 `polishText` 扩展确定性规则：

- 清理多余空格、重复标点和口语连接词；
- 将常见口语表达替换为中性书面表达；
- 补齐必要标点，整理段落和连接关系；
- 不扩写事实、不生成新观点、不补充引用、不改变摘录原文；
- 在编辑器内同时展示“原文 / 优化建议 / 差异说明”，用户只能主动选择“采用建议”“继续编辑”“保留原文”；
- 保存时记录原文和采用版本，允许随时恢复原文；摘录类型默认禁用润色。

为了保持诚实的产品表达，界面文案使用“轻度表达优化”或“本地规则润色”，不使用“AI 润色”“智能改写”等暗示性表述。第一版不会伪装成语义理解：对超出规则能力的文本，保持原文并提示“未发现适合的本地优化项”。

## 初步文件范围（实施时）

- `.github/workflows/deploy-pages.yml`、`vite.config.js`、`index.html`、`README.md`、新增 `docs/DEPLOY_GITHUB_PAGES.md`：GitHub Pages 构建、部署、项目页路径、PWA 资源路径和无命令行发布说明。
- `public/manifest.webmanifest`、`public/sw.js`、`src/main.jsx`：以部署 base URL 注册 Service Worker、生成 manifest/scope/start URL、处理缓存与离线回退，不把资源路径写死为 `/`。
- `src/App.jsx`：极简书架工作台、分类管理面板、批量归类、笔记的原文/建议对照润色流程与路由状态；拆出只订阅轻量书架摘要的页面级状态。
- `src/useLibrary.js`、`src/db.js`、`src/domain.js`：主分类 CRUD（含重命名/批量事务）、按需 repository 查询、笔记原文版本与本地规则润色数据模型。
- `src/textPolish.js`：可解释的轻度润色规则、差异计算与防止摘录变更的保护逻辑。
- `src/styles.css`：设计 token、书架/抽屉/批量操作/原文建议对照的响应式视觉系统。
- `tests/*`：分类事务、批量归类、筛选性能、纯本地润色规则、GitHub Pages 项目页路径、PWA 与部署 smoke 测试。

- 本期不配置自定义域名；后续如有域名，可按 GitHub Pages 官方流程添加，不改变数据和分类功能。

## 方案依据

- GitHub Pages：使用 GitHub Actions 作为发布来源；项目页需配置相对仓库路径。
- Vite 静态部署：GitHub Pages 项目站点应设置与仓库名对应的 `base`。
